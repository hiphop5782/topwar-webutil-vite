# AI 데이터 조회

브라우저가 `VITE_OLLAMA_URL`(기본 `https://ax.progamer.info`)의 `/api/chat`을 직접 호출한다. 중계 API나 Ollama 서버 코드는 변경하지 않는다. `qwen3:8b`가 구조화된 조회 계획을 만들고, 브라우저의 `dataQuery.js`가 검증·조회·집계한다. 모델이 작성한 데이터 설명은 결과로 사용하지 않는다.

## 지원 범위

- 유저 비교·요약: 현재 닉네임/UID, 서버, 길드, 레벨, 전투력, 조사 시각.
- 길드 비교: 서버 + 길드 태그/이름/ID. 동일한 태그의 다른 서버 길드는 구분한다.
- 서버 비교·요약: 수집 인원, 전투력 수집 인원, 합계, 평균, 최대 전투력.
- 서버 히스토리: 감지된 서버 이동의 유입·유출 건수와 최신 50건. 날짜 미지정 시 최근 30일, 시간 기준 UTC.
- 비교 대상은 2~4개, 요약·이력은 1개. 동명이인은 후보를 표시하고 추가 정보를 요청한다.
- 페이지 이동은 별도 action으로 유지한다. 데이터 질문은 페이지를 자동 이동하지 않는다.

최신 통합 스냅샷은 기존 repository 캐시를 재사용한다. 최초 조회에는 전체 통합 스냅샷 다운로드가 필요하다. 이동 이력은 파일 날짜와 감지 날짜가 다를 수 있으므로 전체 파일을 최대 4개씩 조회한 다음 감지 날짜로 필터링한다. 실패 파일은 불완전 집계로 표시한다. 재조회는 기존 메모리 캐시를 이용한다.

## 정확도와 제한

숫자는 코드로 집계하며 누락 전투력은 0으로 취급하지 않는다. 중복 UID와 동일 이동 이벤트는 중복 집계하지 않는다. 수집 인원은 게임 전체 인원이 아니다. 데이터 결과에는 원본 파일과 수집 시각, 표본 한계를 표시한다.

Ollama에는 질문, 제한된 최근 대화, 직전 조회의 대상/기간을 전송한다. 전체 유저 스냅샷이나 결과 표는 전송하지 않는다. 사용자가 입력한 이름·UID는 질문에 포함되므로 해당 모델 서버로 전송된다. 결과 표는 React 텍스트로 렌더링한다.

현재 서버 히스토리는 이동 기록만 지원한다. 과거 전투력 시계열, 길드 구성 변화, 카르츠·전투 병력 기준 비교, 공략 문서 검색은 추가 개발 대상이다. 비교 지표는 실제 전투 승패를 예측하지 않는다. 결과 표의 고정 문구는 현재 한국어다.

## 검증

`node scripts/verify-ai-data-query.mjs`: 집계, 결측치, 중복, 모호한 이름, 날짜, 부분 실패, 동시 요청 제한을 가상 데이터로 검사한다.

로컬 Vite 서버를 시작한 뒤 `node scripts/verify-ai-data-browser.mjs`: 실제 Ollama와 가상 식별자·데이터로 6개 조회 종류, 캐시 재사용, 자동 이동 방지, 모바일 넘침을 검사한다. AI 호출이 발생한다.
